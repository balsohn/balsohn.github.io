💻 기술: Java 17, Spring Boot 3.x, JPA, MySQL, Redis, Spring Security, JWT, OAuth2, AWS(ECS/Fargate, RDS, S3), GitHub Actions

내가 맡은 영역

  • Place 도메인: Google Places 응답 → 내부 Place 변환/저장, 장소 검색/상세, 북마크·리뷰·평점 API
  • Payments 환불: 환불 승인/콜백 검증, 상태 전이(REQUESTED→APPROVED/REJECTED) 및 금액/서명 검증
  • 배포: GitHub Actions → ECR/ECS(Fargate) 자동 배포, ALB 헬스체크/롤백 기준 구성
  • S3 이미지 업로드: 버킷/폴더 구조 설계, 업로드 API와 URL 관리, 최소 권한 정책(least privilege)

문제 해결

  • Places API 비용/쿼터: Redis 캐시 TTL/키 전략, 리뷰/북마크 변경 시 정확한 캐시 무효화
  • 환불 중복 콜백: 주문별 idempotency 키와 상태 전이 규칙으로 중복 처리 방지, 금액/서명 검증
  • S3 업로드 안정성: Content-Type/확장자 검증과 퍼블릭 접근 제어로 잘못된 파일/권한 노출 방지
  • 배포 신뢰성: ALB 헬스체크 실패 시 자동 롤백, 단계적 배포로 무중단 전환

아키텍처 특징

  • DDD 기반 도메인 설계: auth, courses, places, payment, eventproduct, order, user
  • Security Multiple FilterChain: 공개/인증 API 분리, JwtFilter 적용 범위 최소화
  • Redis 캐싱: 외부 API 응답/목록 캐싱으로 비용/응답속도 최적화
  • AWS 배포: ALB → ECS Fargate(Spring Boot+Redis) → RDS(MySQL), S3 이미지 저장, Parameter Store

백엔드 API 설계

  • RESTful 설계 원칙 적용: 도메인별 버전 경로, 표준 응답 포맷, 에러 코드 일원화
  • 페이지네이션/정렬/필터링 공통 파라미터 적용
  • DTO/Projection 기반 조회로 N+1 방지 및 응답 축소
  • 토큰 블랙리스트 기반 로그아웃, Refresh 토큰 회전 전략

결제/환불 플로우

  • 주문 생성(PENDING) → 결제 승인(CALLBACK 검증) → 확정(CONFIRMED) / 환불(CANCELLED)
  • 서명/금액 검증과 중복 콜백 대비 Idempotent 처리
  • 결제 실패/타임아웃 시 재시도 가이드와 안전한 롤백
